## 1. 컨셉

> **아이디어와 사이트를 모아놓는 서랍. 일단 작게 시작하고, 추후 업데이트로 키운다.**

v1은 두 가지만 담는다 — **사이트 모음**(카테고리별 링크)과 **아이디어**(메모).
초안 5.5의 나머지 기능은 폐기가 아니라 §7 추후 업데이트 풀로 내린다.

## 2. v1 범위

### 2.1 수집 유형 (2종으로 축소)

| 유형 | 내용 |
|---|---|
| **사이트** | URL + 제목·썸네일(자동 추출) + **도메인·파비콘**(외부 URL 직접 참조 — 서버 복사 금지 원칙 준수) + 카테고리 + 한 줄 메모. 썸네일 없는 사이트의 식별용 (IMP-03) |
| **아이디어** | 마크다운 텍스트 (프로젝트가 아직 아닌 생각들) |

- **URL 메타데이터 자동 추출은 v1에 유지** — 붙여넣으면 `og:title`·썸네일 자동 채움.
  체감 만족도가 가장 큰 기능 (초안 유지)
- 코드 스니펫·파일/이미지 유형은 추후 (§7)

### 2.2 카테고리

- 사이트의 분류는 **단일 카테고리 필드**: 기본 4종 `디자인 / 개발 / 기획 / 기타`
- 설정에서 카테고리 추가·이름 변경 가능 (확장 대비)
- 태그(자유 입력 + 자동완성)는 카테고리와 별개로 공통 레이어 그대로 사용 —
  카테고리는 "어느 서랍", 태그는 "가로지르는 라벨"

### 2.3 화면

```
┌──────────┬────────────────────────────────┐
│ 전체      │  [카드/리스트 토글]   [검색]      │
│ 디자인    │                                │
│ 개발      │  ▢ 사이트 카드: 썸네일·제목·메모   │
│ 기획      │  ▢ ...                         │
│ 기타      │                                │
│ ──────   │                                │
│ 아이디어  │                                │
└──────────┴────────────────────────────────┘
```

- 좌측: 카테고리 필터 + 아이디어 섹션
- 검색: 제목·메모 대상 `LIKE` (전문 검색은 추후)
- 라우팅: `/resources` (필터는 쿼리), `/resources/:id` (아이디어 상세·수정)

### 2.4 등록 경로

| 경로 | 동작 |
|---|---|
| 전역 인박스 (⌘K) | URL → 사이트로 **기본 카테고리 '기타' 즉시 저장**, 분류는 자료수집 페이지에서 후처리 — 클릭 1~2회 원칙 유지 (USE-02). 그 외 텍스트 → 아이디어 |
| 페이지에서 직접 | [+] 버튼, URL 붙여넣기 즉시 메타 추출 |
| 북마클릿 (v0.2) | 현재 페이지를 인박스로 POST. **인증은 전용 캡처 토큰**(북마클릿 URL에 포함) + 서버 라우트 검증 — RLS 환경에서 익명 POST는 불가하므로 v0.2 착수 전 확정 (ISSUE-01) |

- **인박스 "아이디어" 처리의 종착지가 여기다** — 프로젝트 아이디어는 프로젝트 `idea`
  상태로, 일반 아이디어는 자료수집으로. 인박스 처리 버튼에서 갈린다

## 3. 데이터 모델

```
resources   id, type,            -- site | idea  (추후: snippet | file)
            url?, title, memo, content?, thumbnail?,
            category?            -- 사이트만. 기본 4종 + 사용자 정의
```

- 초안의 `summary`, `read_status`는 추후 기능(본문 아카이빙, 읽기 큐)과 함께 도입 —
  v1 스키마에 미리 넣지 않는다 (YAGNI)
- 카테고리 목록은 설정에 저장 (별도 테이블 불요, 배열이면 충분)

## 4. 다른 영역과의 연결

| 대상 | 내용 |
|---|---|
| 인박스 | URL → 사이트, 텍스트 아이디어 → 여기로. 자동 추정 규칙(기획서 4.2) 그대로 |
| 프로젝트 | 아이디어를 "프로젝트로 승격" 버튼 → 프로젝트 `idea` 생성 (원본은 링크로 남김) |
| 런처 타일 | 표시 정보 조정: 안 읽은 수 → **이번 주 수집 수** + 인박스 미처리 수 (read_status가 추후로 밀렸으므로) |

## 6. 결정 이력 (2026-08-27)

| # | 항목 | 확정 |
|---|---|---|
| R1 | v1 범위 | **사이트 모음 + 아이디어 2종만.** 나머지는 추후 업데이트 풀 |
| R2 | 사이트 분류 | **단일 카테고리 필드**, 기본 4종(디자인/개발/기획/기타) + 사용자 추가 |
| R3 | 인박스 "아이디어" 종착지 | **자료수집** (프로젝트 아이디어는 프로젝트 `idea`로 분기) |
| R4 | 런처 타일 숫자 | 안 읽은 수 → 이번 주 수집 수 (읽기 큐가 추후로 밀림) |

**이 영역에 남은 미결정 사항은 없다.**

## 7. 추후 업데이트 풀 (초안 5.5에서 이월)

버전 미배정. 실사용 후 필요가 체감되는 순서로 도입한다.

| 기능 | 내용 |
|---|---|
| 코드 스니펫 유형 | 코드·언어·설명·사용처 |
| 파일·이미지 유형 | 스크린샷, PDF (WebP 압축 규칙은 기획서 8.2 유지) |
| 본문 아카이빙 | Readability 계열 본문 추출·저장 — 원본이 죽어도 내 자료는 남는다 |
| 읽음 상태 | 나중에 읽기 큐 (`unread → reading → done ↘ archived`) |
| 전문 검색 | Postgres `tsvector` (v1은 `LIKE`) |
| 프로젝트 연결 | 자료 ↔ 프로젝트 N:M |
