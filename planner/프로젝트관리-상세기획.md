## 1. 컨셉

> **프로젝트의 일생을 게이트로 관리한다.**

프로젝트는 상태를 따라 흘러가고, 상태가 바뀌는 순간마다 "이때 정리해야 하는 것들"이
게이트로 붙는다. 킥오프·개발 시작·플랫폼 선정·회고가 별도 기능이 아니라
**상태 전이의 부산물**이 되도록 한다 — 타임로그가 시간 추적을 흡수한 것과 같은 원리다.

```
(등록) → idea → planning → active → live → completed
        G0     G1        G2       G3      G4
        씨앗   킥오프     개발시작   플랫폼   회고
                            ↕
                          paused

※ 어느 상태에서든 → dropped (폐기. G4 회고를 거친다)
```

- **종착 상태를 `completed`(완주)와 `dropped`(폐기)로 분리한다** (`archived` 폐지).
  폐기도 지우지 않는다. 회고의 "다음에 안 할 것"이 폐기 프로젝트에서 특히 값지다
  — 기획서 6장 dropped 철학과 동일
- `paused`는 `active`에서만 오간다
- **역전이 허용**: 실수로 종료했거나 폐기를 되살릴 때 `completed / dropped → active`로
  되돌릴 수 있다. 전이는 `project_events`에 기록되어 타임라인에 남는다 (BUG-04)

### 1.1 관리 그룹 — 화면에서는 4개로 묶는다 (확정)

상태는 게이트를 위해 세분화를 유지하되, 목록·관리의 단위는 4개 그룹이다.

| 그룹 | 포함 상태 |
|---|---|
| **진행중** | `active`, `live` |
| **대기중** | `idea`, `planning`, `paused` |
| **완료** | `completed` |
| **폐기** | `dropped` |

## 2. 게이트 정의

### 2.1 게이트별 정리 항목

| 게이트 | 전이 | 이때 정리하는 것 |
|---|---|---|
| **G0 씨앗** | (등록) → `idea` | 제목(유일한 필수) + 한 줄 메모. 마찰 없이 |
| **G1 킥오프** | `idea → planning` | 목적(왜 만드나), 타겟(누구를 위해), 범위 — **만들 것 / 안 만들 것**, 기술스택 후보 |
| **G2 개발 시작** | `planning → active` | 저장소 URL, 기술스택 확정, 마일스톤 초안, 첫 태스크 3개, 프로젝트 색상 확인(자동 배정) |
| **G3 플랫폼 선정** | `active → live` | 배포 플랫폼(Vercel·스토어 등), 배포 URL, **운영 환경 등록 → 운영·배포 영역 핸드오프** |
| **G4 회고** | `→ completed / dropped` | 회고 템플릿 작성 (§5.4) |

- 범위의 "안 만들 것" 항목을 명시적으로 둔다 — 기획서 2.2가 시스템 전체에 한 일을
  각 프로젝트에도 하게 만드는 장치다
- G3의 상세(플랫폼 값 목록, 환경·체크리스트 구조)는 **운영·배포 영역 상세 기획에서 정의**

### 2.2 게이트 UX — 소프트 강제 (확정)

```
[planning으로 →] 클릭
  → 게이트 카드가 뜬다: G1의 빈 항목 폼
  → 채우고 전이  또는  [나중에 채우기]로 건너뛰고 전이
```

- **전이를 막지 않는다.** 전이 순간이 정리하기 가장 자연스러운 타이밍이므로 카드를
  들이밀되, 귀찮으면 통과
- 건너뛴 항목은 개요 탭에 빈칸으로 남고, **채움도(예: 킥오프 3/4)** 로 표시
- 게이트 카드 항목 수는 5개 이하 유지. 늘어나면 게이트가 관문이 아니라 벽이 된다

## 3. 라우팅

/projects/:id          상세 — 탭: 개요 / 태스크 / 문서 / 회고

  기능 명세 템플릿으로 흡수. 탭은 4개로 고정

## 4. 목록 (/projects)

- **4개 관리 그룹** 순서: 진행중 → 대기중 → 완료(접힘) → 폐기(접힘)
- 대기중 카드에는 세부 상태 배지(idea / planning / paused) 표시
- 카드 구성: 색상 도트 + 제목 + 진행률 바(4px) + 최근 활동일 + **이번 주 투입 시간**(타임로그 집계)
- 대기중 그룹에서는 진행률 바를 숨긴다 — 태스크가 없어 항상 0%인 빈 바 방지 (ISSUE-08)
- **`idea` 그룹이 곧 아이디어 풀이다.** 별도 "아이디어 인박스" 화면은 두지 않는다 (확정)
  - 등록 경로: 전역 인박스에서 "프로젝트 아이디어"로 처리 → `idea` 프로젝트 생성,
    또는 목록에서 직접 [+]
- 정렬: 그룹 내 최근 활동순

### 진행률 계산 (초안 유지)

```
진행률 = Σ(마일스톤별 태스크 완료율 × 마일스톤 가중치)
```

- 마일스톤이 없으면 태스크 개수 방식으로 폴백
- **`dropped` 태스크는 분모에서 제외** — 그렇지 않으면 영원히 100%가 안 나온다
- 서버에서 계산해 `projects.progress`에 캐싱. 매번 조인하면 메인 화면이 느려진다

## 5. 상세 탭

### 5.1 개요 — 게이트에서 채운 것들이 사는 곳

- **생애 타임라인** — 탭 상단 (§5.5)
- 목적 / 타겟 / 범위(만들 것·안 만들 것) — G1
- 기술스택, 저장소 URL — G2
- 플랫폼, 배포 URL, 운영 환경 요약 — G3 (운영 영역으로 링크)
- 게이트 채움도 표시 (미채움 항목은 빈칸으로 노출 — 채우라는 압박은 채움도 숫자까지만)
- 연결된 연간 목표 (연별 TO DO에서 프로젝트 연결한 항목)
- 시간 집계: 총 투입 시간 · 이번 주 투입 시간 (타임로그 집계. 상세 통계는 v0.6)
- 마일스톤 요약 (다음 마감 1~2개)

### 5.2 태스크 — 칸반 + 마일스톤

- 칸반: `todo / doing / done` 3열 + `dropped`는 접힌 영역
- 마일스톤: 제목·마감일·가중치. **마감일은 달별 캘린더의 마일스톤 레이어로 자동 노출**
- 태스크를 일별 기록지의 백로그/오늘 할 일로 끌어오기 (`planned_date`) — 일정 영역과 연결
- 타임로그 블록을 태스크에 연결하면 `actual_min` 누적 (일정 상세기획 §4.4)

### 5.3 문서 — 마크다운 문서 목록 (확정)

- 제목 + 마크다운 본문의 단순 문서 목록. 에디터는 textarea + 미리보기 수준, 고도화하지 않는다
- **템플릿 4종 프리셋**: 기능 명세 / 화면설계 / ERD / API 스펙
  - 새 문서 생성 시 템플릿 선택 또는 빈 문서
- 문서는 프로젝트 소속. 프로젝트와 무관한 글은 자료수집 영역의 메모가 담당 (성격 분리)

### 5.4 회고 — 4문항 + 자동 수치 (확정, 미결정 #5 닫힘)

```
── 자동 삽입 ──────────────────────────
기간 2026-03-01 ~ 2026-08-20 (172일)
총 투입 61h · 완료 태스크 47 · 드롭 9 · 배포 12회
──────────────────────────────────────
1. 잘한 것
2. 아쉬운 것
3. 배운 것
4. 다음에 안 할 것        ← 가장 중요한 문항
```

- `completed / dropped` 전이 게이트(G4)에서 작성. 건너뛰면 목록 카드에 "회고 미작성" 배지 —
  이 배지는 예외적으로 상시 허용 (조용함 원칙의 예외: 회고는 이 도구의 존재 이유 중 하나).
  색은 **중립 회색** — 🔴/🟡 경고 체계와 분리해 압박을 최소화한다 (USE-07)
- 종료 회고 1건으로 시작. 중간 회고는 만들지 않는다 — 중간 기록은 데일리 노트와 문서가 담당

### 5.5 생애 타임라인 — "이 프로젝트를 어떻게 진행했나" (확정)

개요 탭 상단에 표시. **입력을 받지 않고 기존 데이터에서 자동 생성**된다 —
게이트 구조의 부산물이다.

```
│ idea ██ planning ████ active ██████████████ live ████████→
│      ↑G1         ↑G2      ◆MVP     ▲v0.1     ↑G3   ▲v0.2
└──────────────────────────────────────────────────────────
  3/1   3/10       4/2      5/15     6/1       8/20   9/2
```

- **간트형 상태 구간 바**: 상태 전이 이력(`project_events`)으로 각 상태의 체류 구간을
  가로 바로 표시. 구간 색은 상태별 고정
- **마커**: 마일스톤 완료(◆), 배포(▲), 회고 작성(●)을 바 위에 겹침
- 마커 클릭 → 하단 이벤트 목록(세로)에서 해당 항목 하이라이트
- 데이터 소스는 조회 시 병합: `project_events`(전이) + `milestones` + `deployments`
  + `retrospectives`. 별도 저장 뷰 없음
- 폐기 프로젝트의 타임라인은 회고와 함께 "어디서 멈췄나"를 보여주는 자료가 된다

## 6. 데이터 모델 변경

### 6.1 확장: `projects`

```
projects    ... 기존 컬럼 + purpose, target_user,
            scope_in, scope_out,        -- 만들 것 / 안 만들 것
            tech_stack, platform?       -- platform 값 목록은 운영 영역에서 정의
```

### 6.2 신설: `documents`

```
documents   id, project_id, title, content(md), template_type?, updated_at
```

### 6.3 신설: `retrospectives`

```
retrospectives  id, project_id(unique), good, bad, learned, never_again,
                stats(json), created_at     -- stats: 작성 시점 수치 스냅샷
```

- 수치는 조회 시 계산이 아니라 **작성 시점 스냅샷** — 이후 데이터가 변해도 회고는 그대로
- 역전이 후 재종료 시 기존 행을 재사용한다 (unique 유지) — 회고는 수정으로 갱신 (BUG-04)

### 6.4 신설: `project_events`

```
project_events  id, project_id, type, from_status?, to_status?,
                occurred_at, note?
```

- **상태 전이 시 자동 기록.** 수동 입력 없음
- 생애 타임라인(§5.5)의 뼈대. 마일스톤·배포·회고는 각자의 테이블에서 조인
- v0.3부터 로깅을 시작해야 타임라인 UI가 나올 때(v0.5) 그릴 데이터가 있다

## 7. 다른 영역과의 연결

| 대상 | 내용 |
|---|---|
| 일정 — 달별 | 마일스톤 마감일 → 마일스톤 레이어 (읽기 전용) |
| 일정 — 일별 | 태스크 `planned_date` 끌어오기, 타임로그 → 투입 시간 집계 |
| 일정 — 연별 | 연간 목표의 프로젝트 연결 → 개요 탭 노출. 연별 항목 [프로젝트로 만들기] → `idea` 생성 (USE-05) |
| 인박스 | "프로젝트 아이디어" 처리 → `idea` 생성. `#프로젝트명` → 해당 프로젝트 태스크 |
| 운영·배포 | **G3 핸드오프**: 플랫폼·환경 등록·배포 체크리스트. 상세는 운영 영역 기획에서 |
| 런처 타일 | 기존 규칙 유지 (진행 중 수 / 최근 활동 + 진행률 / 배지) |
| GitHub 연동 (v0.6) | **읽기 전용** — 커밋·이슈·PR을 개요/태스크에 표시만. 양방향 동기화는 하지 않는다 |
