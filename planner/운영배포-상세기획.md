## 1. 컨셉

> **라이브 프로젝트의 살림살이. 시스템은 안내와 기록만 하고, 판단은 사람이 한다.**

- **시크릿 값은 저장하지 않는다** — "어떤 키가 어디에 있는지" 메타데이터만 (초안 원칙 유지)
- **가격도 같은 원칙이다** — 자동 수집하지 않는다. 가격 페이지는 크롤링이 계속 깨지는
  영역이고, 실제 청구액은 사용량에 따라 다르다. 시스템은 링크와 기록만 담당한다
- 개인 개발자 도구에서 가장 비어 있는 영역이라 차별점이 된다 (초안 유지)

## 3. 플랫폼 카탈로그 (신설)

### 3.1 개념

"어떤 플랫폼·서비스들이 있는지"를 시스템이 **시드 데이터로 추천**하고, 사용자는
거기서 고르거나 직접 추가한다. 프로젝트 영역에서 이관된 **"G3 플랫폼 값 목록"의 답**이
이 카탈로그다 — G3 게이트의 플랫폼 선택도 여기서 고른다.

### 3.2 항목 구성

```
이름 / 카테고리 / 홈페이지 URL / 가격 페이지 URL / 무료 티어 메모
```

- 시드 항목도 수정·삭제 가능 (내 데이터), 직접 추가 항목은 `is_custom` 표시
- 가격 페이지 URL이 §4 가격 체크 플로우의 [가격 페이지 열기] 버튼이 된다

### 3.3 시드 카테고리 (확정 — 4종 전부)

| 카테고리 | 시드 예시 |
|---|---|
| 웹·클라우드 인프라 | Vercel, Netlify, Cloudflare(Pages·Workers), Supabase, Railway, Render, Fly.io, AWS, GitHub Pages |
| 게임 플랫폼 | Steam(Steamworks $100/게임), itch.io(무료), Epic Games Store |
| 모바일 스토어 | Google Play($25 1회), App Store($99/년) |
| 도메인·구독 서비스 | 가비아, Namecheap, Cloudflare Registrar, OpenAI API, Anthropic API, UptimeRobot, Sentry |

시드 상세 목록(가격 페이지 URL 포함)은 구현 시 JSON으로 확정한다.

## 4. 가격 체크 플로우 (확정 — 3단계 수동)

```
[서비스 추가] → 카탈로그에서 선택 (또는 직접 입력)
  → ① [가격 페이지 열기] 버튼          시스템이 링크 제공
  → ② 확인한 가격·주기·통화 입력        사람이 직접 체크
  → ③ [확인] → 가격 + 확인일 저장       price_checked_at 기록
```

### 규칙

- **확인일(`price_checked_at`)을 가격과 함께 저장한다.** "확인" 버튼의 실질이 이것이다
- **신선도 표시**: 확인 후 90일이 지나면 가격을 흐리게 표시 + "재확인" 링크.
  배지·알림은 쓰지 않는다 — 조용함 원칙
- **갱신 D-7 알림에 가격 재확인 딥링크를 얹는다.** 갱신 직전이 가격 인상을 확인할
  최적 타이밍이라, 재확인 루프가 기존 알림에 공짜로 실린다
- **통화는 통화별 그대로 기록한다** (확정). 환산 입력·환율 API 없음.
  합계는 통화별 병기: `월 $25 + ₩3,300`
- **합계 규칙**: 월 주기만 월 합계에 포함하고, 연 주기는 별도 병기한다 —
  연→월 환산(÷12)을 하지 않는다 (ISSUE-09)

## 5. 대시보드 (/ops)

- **운영 중(live) 프로젝트 카드**: 헬스체크 상태, 최근 배포, 도메인·SSL 만료 D-day
- **만료 임박 (D-30 내)**: SSL, 도메인, 구독 갱신을 한 목록으로
- **비용 요약**: 월 환산 통화별 합계 + 가격 재확인 필요 항목 수(흐림)
- 런처 타일(운영 중 서비스 수 / 헬스 상태 / 다운·만료 배지)의 데이터 소스
- **환경 미등록 live 프로젝트** (G3를 건너뛴 경우): 카드에 "환경을 등록하세요" 빈 상태
  + [G3 카드 다시 열기] 버튼 — 소프트 강제의 뒷수습 (ISSUE-04)

## 6. 환경 관리 (초안 유지 + 카탈로그 연결)

- dev / staging / prod별: 서버 정보, 도메인, SSL 만료일, 호스팅 스펙
- 환경에 플랫폼 연결 (`platform_id`) — "prod는 Vercel, DB는 Supabase"
- 시크릿은 메타데이터만: 키 이름 · 보관 위치(예: Vercel env, 1Password) · 용도

## 7. 배포 이력 + 체크리스트

### 7.1 배포 기록 — 수동 (v0.5)

```
[+ 배포 기록]
  프로젝트 / 환경 / 버전 / 변경사항 / 배포 일시
  □ 체크리스트 확인
```

- 배포 이력은 프로젝트 생애 타임라인의 ▲ 마커로 노출 (프로젝트 상세기획 §5.5)
- 변경사항 누적 → 릴리즈 노트 자동 생성 (초안 유지)

### 7.2 배포 전 체크리스트 (이관 항목 해결)

- **템플릿**: `checklist_templates` — 기본 시드 1종 제공
  (환경변수 확인 / DB 마이그레이션 / 백업 확인 / 롤백 계획), 프로젝트별 커스텀 가능
- **스냅샷**: 배포 기록 시 체크 결과를 `deployments.checklist_snapshot`에 저장 —
  템플릿이 나중에 바뀌어도 "그때 뭘 확인했는지"는 남는다

### 7.3 반자동 (v0.6) — 초안 유지

```
Vercel 배포 완료 → Webhook → /api/webhooks/vercel
  → deployments 자동 INSERT → 커밋 메시지를 changelog 초안으로
```

수동 입력만 있으면 3번쯤 하다 안 하게 된다. 이 페이지의 성패를 가르는 지점.

## 8. 모니터링 · 장애 (초안 유지)

- 헬스체크는 UptimeRobot에 위임. 다운 알림은 UptimeRobot → Discord 직행 (SPM 중계 없음)
- **`/api/health`는 가벼운 DB 조회를 포함해야 한다** — 정적 응답이면 Supabase 7일
  무활동 정지를 막지 못한다 (ISSUE-05)
- 장애 기록: 발생 → 원인 → 조치 → 재발방지. 프로젝트 타임라인에는 올리지 않는다
  (타임라인은 진행의 기록, 장애는 운영의 기록 — 성격 분리)

## 9. 비용 관리

- `costs` 확장: 플랫폼 연결(`platform_id`), 통화, 가격 확인일
- 갱신일 D-7 알림 (초안 유지) + 가격 재확인 딥링크 (§4)
- **무료 티어도 0원으로 등록한다** — 비용 목록이 곧 "내가 지금 뭘 쓰고 있나" 인벤토리가
  된다. 무료 티어 한도 메모는 카탈로그의 free_tier_note 참조

## 12. 결정 이력 (2026-08-27)

| # | 항목 | 확정 |
|---|---|---|
| O1 | 가격 수집 방식 | **3단계 수동** — 링크 버튼 → 직접 확인 → 확인 저장(+`price_checked_at`) |
| O2 | 카탈로그 시드 범위 | **4개 카테고리 전부** (웹·클라우드 / 게임 / 모바일 스토어 / 도메인·구독) |
| O3 | 통화 처리 | **통화별 그대로 기록**, 합계는 통화별 병기. 환율 변환 없음 |
| O4 | 가격 신선도 | 90일 경과 시 흐림 + 재확인 링크. 배지·알림 없음 |
| O5 | 장애의 타임라인 노출 | 하지 않음 — 진행의 기록과 운영의 기록 분리 |

**이 영역에 남은 미결정 사항은 없다.** 시드 카탈로그 상세 목록만 구현 시 JSON으로 확정.
