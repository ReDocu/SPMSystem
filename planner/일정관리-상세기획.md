## 1. 컨셉

> **계획은 내려가고, 기록은 올라간다.**

세 개의 뷰가 각각 다른 시간 해상도와 다른 성격을 가진다.

| 뷰 | 시간 축 | 성격 | 다루는 개념 |
|---|---|---|---|
| **일별** | 하루 | 기록지 — 오늘 실제로 **무엇을 했는가** | 타임로그 + 오늘 할 일 + 데일리 노트 |
| **달별** | 한 달 | 현황판 — 프로젝트가 **어떻게 흘러가는가** | 타임로그 요약 + 일정(event) + 마감 + 마일스톤 |
| **연별** | 1년 | 계획 — 올해 **무엇을** 할 것인가 | 연차별 목표 TO DO LIST + 기념일 조망 |

- 내려가는 방향: 연별 항목에 날짜가 붙으면 달별에 나타나고, 그날이 되면 일별의 참조가 된다
- 올라가는 방향: 일별 기록이 쌓여 달별 현황이 되고, 연말에는 연간 회고 자료가 된다
- **달별은 계획(내려온 마감·마일스톤)과 실적(올라온 타임로그)이 만나는 화면이다**

## 2. 데일리 루틴 — 매일 기록하는 것들

로그인 → 일별 기록지가 열린다. 매일의 기록 항목은 세 등급으로 나눈다.
**타임로그만 채우면 그날의 의무는 끝이다.** 나머지는 곁에 있는 낮은 마찰의 옵션.

| 등급 | 항목 | 규칙 |
|---|---|---|
| **필수** | 타임로그 | 이것 하나만 해도 하루 기록이 성립 |
| 권장 | 오늘 할 일 체크, 인박스 캡처 | 자연스럽게 따라오는 것 |
| 선택 | 데일리 노트 한 줄, 컨디션 1탭 | 안 해도 아무 압박 없음 — 빈칸 배지 금지 |

하루의 흐름으로 보면:

```
아침 (계획 · 선택적)   백로그에서 오늘 할 일 끌어오기, 오늘 일정 확인
낮   (수시 · 메인)     타임로그 기록 (+프로젝트 연결), ⌘K 인박스 캡처
저녁 (마무리 · 선택적)  할 일 체크, 데일리 노트 한 줄, 컨디션 1탭
```

## 3. 라우팅

```
/schedule                      → 오늘 일별 뷰로 리다이렉트
/schedule/day/:date            일별  (예: /schedule/day/2026-08-27)
/schedule/month/:yyyy-mm       달별  (예: /schedule/month/2026-08)
/schedule/year/:yyyy           연별  (예: /schedule/year/2026)
```

- 상단에 `일별 | 달별 | 연별` 탭. 탭 전환 시 보고 있던 날짜의 문맥을 유지한다
  (8월 15일 일별을 보다가 달별을 누르면 2026-08이 열린다)
- **기본 진입은 일별(오늘).** 매일 여는 화면은 기록 화면이어야 한다

## 4. 일별 — 기록지

### 4.1 목적

하루 24시간 동안 무엇을 했는지 시간 단위로 직접 입력해 기록한다.
**계획 도구가 아니라 기록 도구다.** 지나간 시간을 적는 것이 기본 동작이다.

### 4.2 레이아웃

```
┌─────────────────────────────┬──────────────────┐
│  타임로그 (00:00 – 24:00)     │  □ 오늘 할 일     │
│                             │    · 로그인 API   │
│  00 ─ (접힘: 00–06)          │    · 병원 예약    │
│  ...                        │  ▸ 백로그 (접이식) │
│  09 ─ SPM 개발 ──┐          │                  │
│  10 ─           │ (블록)    │  ◷ 오늘 일정      │
│  11 ─ ──────────┘          │    15:00 병원    │
│  12 ─ 점심                  │    🎂 결혼기념일   │
│  ── 현재 시각 라인 ──         │                  │
│  14 ─ (빈 슬롯)              │  ✎ 데일리 노트    │
│                             │  ☺ 컨디션        │
└─────────────────────────────┴──────────────────┘
```

- 좌측: 24시간 세로 타임라인. 화면의 주인공
- 우측 패널 (위에서부터):
  - **오늘 할 일** — `planned_date = 오늘`인 태스크. 체크 가능
  - **백로그 (접이식)** — §4.5
  - **오늘 일정** — event, 읽기 전용. 기념일·수업·출장 포함, 카테고리 아이콘 표시.
    지난 시각의 일정에는 **[기록으로 복사]** 원탭 버튼 — 타임로그로 변환해
    "다녀온 병원"의 이중 입력을 없앤다 (USE-01)
  - **데일리 노트** — 한 줄이면 충분한 크기로. 자유 서식 긴 글을 유도하지 않는다
  - **컨디션** — 이모지 1탭 (채택 확정)
- 모바일: 타임라인만 표시, 우측 패널은 상단 접이식 요약으로

### 4.3 입력 UX

기획서 철학 1번(입력 마찰 최소화)이 이 화면의 존재 이유다.

| 동작 | 결과 |
|---|---|
| 빈 슬롯 클릭 | 인라인 입력창 → 텍스트 입력 → Enter 저장 |
| 드래그 (여러 슬롯) | 해당 범위의 블록 생성 후 입력 |
| 블록 클릭 | 인라인 수정 |
| 블록 경계 드래그 | 시간 범위 조절 |
| `#프로젝트명` 포함 | 해당 프로젝트에 연결 + 프로젝트 색상 표시 |

- 기본 단위는 **1시간**. 저장은 분 단위로 하되 UI는 1시간 스냅
- 연속된 같은 활동은 별도 행이 아니라 **하나의 블록**으로 표시
- 오늘 날짜를 열면 현재 시각으로 자동 스크롤, 현재 시각 라인 표시
- 빈 슬롯은 회색으로 조용히 표시. **빈칸을 채우라는 압박(알림·배지)은 주지 않는다** — 철학 3번(조용함)
- 00–06시 구간은 기본 접힘, 펼침 버튼 제공
- **자정을 넘는 블록**(예: 23:00~01:00)은 저장 시 자정 기준 두 행으로 자동 분할하되,
  UI에서는 이어진 하나의 블록으로 표시한다 (BUG-03)
- **모바일은 드래그를 쓰지 않는다** — 터치 드래그는 스크롤 제스처와 충돌하므로
  탭 → 시간 범위 선택 시트 방식으로 대체한다 (ISSUE-02)
- 매일 반복되는 블록(수면·식사·수업 등)은 일별 헤더의 **[어제 블록 복사]** 1버튼으로
  가져올 수 있다 — 선택 실행, 강요 없음 (IMP-01)

### 4.4 시간 추적의 흡수

시간 추적은 별도 기능이 아니라 타임로그의 부산물이다.

```
타임로그 블록을 태스크에 연결
  → 블록 시간이 tasks.actual_min에 자동 누적
  → estimated_min과 비교 → 주간 리포트 (v0.6 통계)
```

- 타이머 시작/정지 방식은 만들지 않는다. 1인 도구에서 타이머는 "켜는 걸 까먹는" 기능이다
- 연결 방법: 블록 입력 시 우측 패널의 오늘 할 일에서 선택, 또는 입력 텍스트로 자동 제안 —
  **부분 일치 + 오늘 할 일 우선 + 최근 연결 이력 순.** 완전 일치 조건만으로는 실사용에서
  거의 발동하지 않는다 (USE-06)

### 4.5 백로그 (신설)

**마감일도 계획일도 없는 미완료 태스크의 목록.** 별도 페이지를 만들지 않고
일별 우측 패널의 접이식 섹션으로 둔다.

- 대상: `status = todo` 이고 `planned_date` · `due_date` · `target_year` 가 **모두 없는**
  태스크 (개인 할 일 + 프로젝트 태스크. 프로젝트 태스크는 프로젝트 배지로 구분)
  — `target_year` 제외가 없으면 연간 목표 수십 건이 백로그를 점령한다 (BUG-01)
- 연간 목표는 백로그에 나타나지 않는다. 연별 뷰에서 "오늘 하기"로 끌어올 때만
  `planned_date`가 부여된다
- **백로그 항목을 "오늘 할 일"로 끌어오는 동작 = `planned_date`에 오늘 날짜 지정.**
  이것이 데일리 루틴의 "오늘 할 일 선정"이다
- 미완료된 오늘 할 일은 다음 날 자동 이월하지 않는다 — `planned_date`가 지난 항목은
  **"못 한 일 (n)"** 섹션에 누적 표시했다가 재선정하거나 백로그로 돌려보낸다.
  7일이 지나면 자동으로 백로그에 반환한다 (ISSUE-07)

### 4.6 하루 요약

타임라인 하단에 한 줄:

```
기록 9h · #SPM 5h · #블로그 2h · 기타 2h
```

집계는 이것으로 충분하다. 별도 통계 화면은 v0.6 통계로 미룬다.

### 4.7 빠른 캡처 연동

⌘K 자동 추정 규칙(기획서 4.2)에 한 줄 추가:

| 입력 패턴 | 추정 결과 |
|---|---|
| 날짜 없이 시간 범위 (`14-16 SPM 개발`) | **오늘 타임로그** |
| 미래 날짜 + 시간 범위 (`내일 14-16 회의`) | **일정(event)** — 날짜 규칙이 우선한다 (BUG-05) |

어디서든 "방금 뭐 했는지"를 3초 안에 던질 수 있어야 타임로그가 산다.

## 5. 달별 — 프로젝트 현황판

### 5.1 목적

**이번 달 프로젝트가 어떻게 흘러갔는지 파악한다.** 날짜 셀의 주인공은 일정이 아니라
그날의 기록 요약이다. 한 달을 보면 "내가 어느 프로젝트에 시간을 쏟았나"가 히트맵처럼 보인다.

### 5.2 날짜 셀 구성 (레이어)

| 순서 | 레이어 | 표시 | 편집 |
|---|---|---|---|
| 1 | **기록 요약** (주인공) | 그날 타임로그를 프로젝트 색상 띠(비율)로 압축 | 읽기 전용 (일별에서 기록) |
| 2 | 일정 (event) | 카테고리 색상의 제목 바 / 배지 | **이 화면에서 CRUD** |
| 3 | 마감 태스크 | 점 + 제목 | 표시만, 체크는 일별에서 |
| 4 | 마일스톤 · 배포 예정 | 아이콘 배지 | 읽기 전용 (프로젝트/운영 영역 소유) |

- 지난 마감 미완료는 빨간 텍스트 — 런처 타일과 동일 규칙
- 주 시작 요일은 월요일
- **셀 오버플로 규칙**: 표시 우선순위는 기록 띠 > 일정 > 마감 > 마일스톤.
  넘치는 항목은 `+n`으로 접고, 클릭 시 해당 날짜의 일별로 이동 (ISSUE-06)
- 셀 모서리에 그날의 **컨디션 이모지 미니 표시** (설정 토글) — 컨디션 기록의
  열람처를 v0.6 통계 이전에 마련한다 (USE-08)

### 5.3 사이드 패널 — 월간 집계

- 프로젝트별 누적 시간 (타임로그 집계)
- 프로젝트별 완료 태스크 수, 진행률 변화
- 이번 달 남은 마감·마일스톤 목록

### 5.4 일정 카테고리

event에 카테고리 속성 하나를 추가한다. 테이블 추가 없음.

| 카테고리 | 데이터 표현 | 표시 예 |
|---|---|---|
| 일반 | 단발 또는 반복 | 15:00 병원 |
| **기념일** | 연 반복(yearly) + 종일(all_day) | 셀 상단 작은 배지 🎂 |
| **출장** | 여러 날 범위 (시작일~종료일) | 가로 바 |
| **수업** | 주 반복(weekly) + 시간 지정 | 셀 + 일별 "오늘 일정" 패널 |

- 카테고리별 색상 지정
- 기념일은 연별 뷰에도 노출 (§6.4)

### 5.5 반복 일정과 예외

- 반복은 `rrule` 기반
- **단일 회차 취소·변경 지원**: 특정 회차를 취소(EXDATE)하거나 그 회차만 시간 변경
  (예: "이번 주 수업 휴강"). 시리즈 전체 수정과 회차 수정을 구분해 묻는다

### 5.6 상호작용

- **날짜 클릭 → 해당 날짜의 일별 기록지로 이동.** 달별→일별 드릴다운이 기본 내비게이션
- 일정 생성: 빈 셀 더블클릭 → 제목/시간/카테고리 인라인 입력 (모달 금지, 마찰 최소화)
- 일정 드래그로 날짜 이동
- 여러 날 일정(출장 등)은 v1에서 단순 표시, 드래그 리사이즈는 후순위

### 5.7 주간 뷰는 만들지 않는다

주간은 일별과 달별 사이의 애매한 해상도다. 시간 블록킹 욕구는 일별이,
조망 욕구는 달별이 흡수한다. 필요가 체감되면 그때 추가한다 (YAGNI).

## 6. 연별 — 연차별 목표 + TO DO LIST

### 6.1 목적

올해 하기로 한 것들의 목록. 계획의 최상위 층위. 1월에 쓰고 12월에 돌아보는 화면.
연도를 넘나들면 연차별 회고 아카이브가 된다.

### 6.2 구성

```
2026년                                        7/15 완료
─────────────────────────────────────────────
☑ SPM v0.1 실사용 시작          #SPM
☐ 블로그 30편 작성
☐ 이직 포트폴리오 정리
☒ 알고리즘 스터디               (dropped — 하반기 판단)
─────────────────────────────────────────────
🎂 올해의 기념일
  2월  결혼기념일 (D-160)
  9월  부모님 생신 (D-12)
```

- 연도 선택 (기본 올해). 지난 연도는 읽기 전용 아카이브
- 항목: 체크박스 + 제목 + 메모(선택) + 프로젝트 연결(선택)
- 헤더에 `n/m 완료` — 진행률 바는 두지 않는다. 연간 목표에 퍼센트는 압박만 된다
- 정렬: 수동 (드래그). 그룹핑 없이 시작

### 6.3 상태 규칙

- 상태는 기존 Task 상태(`todo → doing → done ↘ dropped`)를 그대로 사용
- **완료·dropped 항목은 지우지 않고 취소선으로 남긴다** — 연말 회고의 원재료다
- 연말 이월: 미완료 항목을 "내년으로 보내기" 또는 `dropped` 선택. 일괄 처리 플로우 제공

### 6.4 기념일 패널 (신설)

- 연별 화면 하단(또는 사이드)에 올해의 기념일을 **월별 그룹 목록**으로 노출
- 다가오는 기념일에 D-day 표시, 지난 기념일은 흐리게
- 여기서도 기념일 추가·수정 가능 (달별과 동일한 event CRUD)

### 6.5 층위 연결

- 연별 항목에 **마감일을 부여하면 그대로 일반 태스크가 되어** 달별·런처·일일 요약에 등장한다 (별도 "승격" 복사가 아니라 같은 데이터)
- 연별 항목을 프로젝트에 연결하면 프로젝트 개요 탭에도 노출
- 연별 항목 컨텍스트 메뉴에 **[프로젝트로 만들기]** — 프로젝트 `idea` 생성 + 상호 연결.
  "미니게임 만들기" 같은 목표는 사실상 프로젝트 씨앗이다 (USE-05)

## 7. 데이터 모델 변경

### 7.1 신설: `time_logs`

```
time_logs   id, user_id, date, start_min, end_min, content,
            project_id?, task_id?, created_at
```

- 1시간 단위로 쓰더라도 **분(min)으로 저장** — 30분 단위 전환에 마이그레이션 불필요
- `task_id` 연결 시 `tasks.actual_min`에 서버 집계 반영 (§4.4)
- 겹침 제약은 DB에 두지 않는다. UI가 슬롯 기반이라 자연히 방지된다
- 한 행은 하루를 넘지 않는다 — 자정을 넘는 기록은 두 행으로 분할 저장 (BUG-03)

### 7.2 신설: `daily_notes`

```
daily_notes  id, user_id, date, content, condition?   -- (user_id, date) 복합 unique (BUG-06)
```

- 하루 1행. 데일리 노트 한 줄 + 컨디션(채택 시)

### 7.3 확장: `schedules`

```
schedules   ... 기존 컬럼 + category      -- normal | anniversary | trip | class
                        + exdates[]      -- 취소된 회차
```

- 회차 단위 시간 변경은 해당 회차를 exdates에 넣고 단발 일정으로 복제하는 표준 방식

### 7.4 확장: `tasks`

```
tasks       ... 기존 컬럼 + target_year?     -- 연별 TO DO 스코프
                        + planned_date?     -- "오늘 하기로 한 날" (§4.5)
```

- `due_date`(마감)와 `planned_date`(하기로 한 날)는 다른 개념이다
- 연별 뷰 = `WHERE target_year = 2026`. 별도 테이블을 만들지 않는다

### 7.5 확장: `projects.color`

타임로그·달별 현황판의 프로젝트 색상 표시를 위해 `projects`에 `color` 컬럼 추가.
**메인 기획서 7장 반영 필요.**

### 7.6 세 개념의 분리 (확정)

| 개념 | 테이블 | 성격 | 주 무대 |
|---|---|---|---|
| task | `tasks` | 완료 개념이 있는 것 (연별 TO DO 포함) | 일별 패널 · 연별 |
| event | `schedules` | 시간을 점유하는 것 (기념일·출장·수업 포함) | 달별 |
| log | `time_logs` | 이미 지나간 시간의 기록 | 일별 |
